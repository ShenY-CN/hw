# 论文图表生成

本目录只放绘图代码；生成的 PDF/PNG 统一写入项目根目录 `figures/`。各脚本读取 `results/` 中已计算并核验的 JSON，不在绘图阶段重新求解。

## 分题入口

| 脚本 | 输出图表 | 主要数据来源 |
|---|---|---|
| `q1.py` | DEM 与节点、最大安全载荷散点图/热力图、典型航线地形剖面、最远服务区载荷—能耗曲线、时间/能耗单目标方案、安全余量敏感性、返航 SOC | `q1_rho*.json`、`q1_energy.json`、`q1_time.json`、共享 `Model` |
| `q2.py` | 运输路线、无人机甘特图、电池任务/充电时间线、逐箱送达时限、返航 SOC、搜索候选比较、架次能耗 | `q2.json`、`method_comparison.json`、共享 `Model` |
| `q3.py` | 中继布设地图、直连盲区的中继覆盖采样图、通信提供方时间轴、链路裕量分布、运输/中继联合甘特图、中继 SOC、Q2/Q3 指标比较 | `q2.json`、`q3.json`、共享 `Model` |
| `q4.py` | 2组/3组分区地图、资源需求与库存、组间工作量、库存缺口、任务关联网络 | `q3.json`、`q4.json`、共享 `Model` |
| `overview.py` | 把可编辑的总体技术路线图 `figures/fig_roadmap.drawio` 渲染为 PDF | DrawIO 源图 |

每个 Q 脚本可单独运行，例如：

```bash
python code/mountain_flood/figure/q2.py
```

完整复现入口会依次运行四个分题脚本和总体路线图渲染脚本。`common.py` 集中管理输出路径、字体样式和 DEM 空间底图，避免各题重复维护地图口径。

《图表安排参考.md》中的算法流程、通信原理等概念示意图不由这四个数据图脚本推算；总体技术路线仍以可编辑 DrawIO 源图维护。尚无对应原始数据或结果字段的建议图，不从缺失数据中编造数值。
