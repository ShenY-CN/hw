# D题复核失败项修复流程

目标：让现有解答可以从原始附件重建、让代码和批准的建模契约一致、给出经回代校验的最好已知方案，并对未证实的全局最优性如实标注。

## 1. 冻结基线与数据契约

- 保留当前输入、正式结果和提交表的哈希与关键指标。
- 记录 Python/依赖版本、随机种子、求解时限、目标优先级及数值容差。
- 从空的结果目录运行，不允许读取旧中间结果补洞。
- 门禁：16 节点、80 唯一货箱、机型和电池库存、DEM 范围、表头及单位均通过；原始附件未修改。

## 2. 第二问：路线与排程

- 把已验证的 1 秒较优排程纳入候选，不直接覆盖正式结果。
- 明确批准的目标顺序：硬约束、加权迟到、最后返航、能耗、架次；排程层采用逐级目标，路线层扩充跨架次移箱、交换、合并、拆分及访问顺序重排。
- 每个候选都要重新检查逐箱唯一覆盖、质量体积、逐段能量、时限、机与电池含充电的区间占用。
- 记录最好可行值、搜索范围、求解器状态及下界；若未闭合全局间隙，只称“最好已知可行解”。
- 门禁：相对旧解按目标顺序不退化；所有硬约束通过；主方案与单点基线使用同一指标。

## 3. 第三问：补齐可执行的联合链

- 从第二问路线计算第三问运输候选；若为分区兼容而拆航次，明确记录拆分理由和成本。
- 用附件参数生成 DEM 内的中继候选点，验证双向接入和回传，生成任务窗口候选；把运输发车、中继服务时段、实体机与能源组件一起排程。
- 对每个候选运行连续轨迹通信证书，不合格则调整候选并重求；不得把旧 JSON 或人工固定时刻伪装成优化输出。
- 同时报告加权迟到、运输/中继能耗、最后返回时刻、硬时限余量、最小链路裕量；与第二问比较并解释变化。
- 门禁：所有 80 箱、硬时限、SOC、实体机和能源组件、连续通信通过；中间文件都由交付代码生成；未证实全局最优则只报可行改进。

## 4. 第四问与最终交付

- 由新第三问结果重新计算不可拆组件、2/3 组枚举及资源缺口；若第三问变化，旧第四问、图表、论文数字全部失效。
- 从同一批 JSON 自动生成提交工作簿和图表；核对六张模板表及新增明细表的行数、字段、单位、逐箱时间和通信合并区间。
- 更新结果报告、论文正文与验证报告，所有数值指向同一次运行。
- 门禁：在隔离目录从只有 `input/` 与 `code/` 的状态运行唯一命令，产出全部结果、工作簿及图；二次运行在声明容差内一致，复现清单包含输入哈希、种子、版本和结果摘要。

## 判定规则

任何运行错误、缺失文件、约束失败、未说明的目标退化或跨文件数值不一致均为 FAIL。第一、四问只能在各自固定模型条件下称最优；第二、三问只有求解器闭合全局间隙时才称全局最优，否则列出最好已知可行解、搜索限制及下界。
